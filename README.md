# Punjab Dairy — Offline Android Milk Shop Manager

An installable, offline-first Punjab Dairy manager written in plain HTML/CSS/JavaScript, with a native Android wrapper using Capacitor. **Source project included; APK is generated by the provided GitHub Actions workflow (not bundled).**

## Included
- Admin account creation and mobile-number/password login; offline admin recovery-code password reset.
- Customer CRUD: registration date, address, mobile, rates for cow/buffalo/yogurt, regular daily quantities, optional customer login.
- Supplier CRUD: contact info, rates, registration date.
- One-by-one daily purchases, customer deliveries and walk-in shop sales; bulk one-date multi-customer or multi-supplier entry.
- Staff CRUD and monthly salaries; expense CRUD.
- Customer/supplier payments and running balances; printable invoice/statement for a chosen date range.
- Day/week/month/quarter/year financial dashboard (sales, litres/kg, purchases, expenses, estimated profit after salary allocation).
- Customer dashboard, profile, deliveries, invoice and feedback on this **same device**.
- JSON backup/import, transactions CSV export and invoice CSV.
- Local IndexedDB, offline service worker for web/PWA installation.

## Important limitations
- **This app stores data only on the device.** It is not a synchronized multi-device service. Customer logins work only on a device with the admin's database; a separate customer phone will not automatically see bills or send feedback to the shop. For that, a secure backend/cloud sync must be added in a future version.
- Offline local login is a privacy convenience, **not a security boundary** against someone who can inspect/modify the device's app storage. Passwords are salted SHA-256 hashes (not recommended as a production server-side password-hashing design). Future hosted service requires server authentication, proper password hashing (Argon2id/bcrypt), TLS and access controls.
- The admin recovery code is required to reset the password offline; if lost, there is no automatic SMS recovery.
- Profit calculation = sales - milk purchased - other expenses - prorated active monthly salaries. Purchases are treated as current-period cost; inventory valuation, unpaid wages, wastage, taxes and accruals are **not** included. Review accounting before relying on it for tax/professional reporting.
- Data can be lost if an app/browser is uninstalled or storage is cleared: **download and keep JSON backups somewhere safe frequently**. Backups include private business/customer data and login hashes; protect them.
- Browser install requires HTTPS and supported browser. Opening `index.html` directly from a file manager is not a reliable installation/offline setup.
- The Android package ID is `pk.punjabdairy.manager`; adjust it before a production Play Store release if needed. Store distribution requires a release-signed build and compliance reviews.

## How to build an APK (no local Android Studio required)
1. Make a new **private** GitHub repository, then upload all files and folders from this project to its `main` branch (including `.github/workflows/build-apk.yml`).
2. Open your GitHub repository → **Actions** → **Build Android APK** → **Run workflow**. On first use, enable workflows if GitHub asks.
3. When the build finishes, open the workflow run → **Artifacts** → download `Punjab-Dairy-Android-APK`.
4. Unzip the downloaded artifact; copy `app-debug.apk` to your Android phone and install it. Android may ask you to allow installation from that source.
5. Launch the app, create an admin account, and **write down the recovery code**. Export a JSON backup after entering your records.

You can alternatively build on a computer with Node.js 22, Java 21 and Android SDK: `npm install`, `npx cap add android`, `npx cap sync android`, `cd android && ./gradlew assembleDebug`. Output: `android/app/build/outputs/apk/debug/app-debug.apk`.

## Preview without APK
Host the `www/` directory on an HTTPS static web host. Open it on Android Chrome and use **Add to Home screen / Install app**. On first launch create the admin login. Once the service worker caches the assets, the UI works offline. HTTPS is necessary for normal PWA support.

## Export and later migration
Admin → **Backup & Settings** → **Export full JSON backup**. This file contains customers, suppliers, users, expenses, staff, transactions, payments and feedback; it is intended as a portable migration source for a future server/Play Store app. `Export transactions CSV` offers spreadsheet-friendly sales and purchase data. A future cloud app must implement a JSON importer and new authentication; installing that future app will **not** automatically transfer local data.

## Suggested first test
Create one customer and a supplier; add a supplier purchase and customer delivery; record a customer payment; check the resulting invoice and customer balance, then export and reimport the JSON backup on a fresh install.
